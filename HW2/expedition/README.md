## 1. Условие задачи
Группа роботов исследует клеточную карту с препятствиями, опасными зонами, целями, зарядными
станциями и ретрансляторами. Роботы получают задания, едут к целям, исследуют их и передают данные
на базу. У роботов ограничены энергия, приборы и память. Связь есть только в зонах базы и
ретрансляторов; сообщения задерживаются, теряются и дублируются. Диспетчер распределяет задания и
повторно назначает потерянные после тайм-аута. База, диспетчер, роботы, зарядные станции и
ретрансляторы — самостоятельные участники модели.

## 2. Сценарий: сущности и потоки

| Участник | Поток | Поведение в потоке |
|---|---|---|
| Часы модели | главный | начинает такт, ждёт всех участников, проверяет инварианты и завершение, рисует карту |
| Робот (×N) | `part_thread` → `robot_tick` | автомат: к цели, исследование, данные, передача, зарядка, стоянка, авария |
| Диспетчер | `part_thread` → `dispatcher_tick` | телеметрия, тайм-ауты, назначение fifo/nearest |
| Узел связи: антенна базы и каждый ретранслятор | `part_thread` → `node_tick` | пересылает сообщения своей зоны: задержка, потеря, дублирование |
| Зарядная станция (×M) | `part_thread` → `charger_tick` | выдаёт энергию роботам на своих разъёмах из запаса |
| База | `base_thread` | не привязана к тактам: спит на семафоре, засчитывает пакеты по номеру, шлёт подтверждения |

Для демонстрационного сценария — 11 потоков (4 робота, диспетчер, 3 узла связи, 2 станции, база)
и главный поток.

**Синхронизация.**

| Примитив | Где | Зачем |
|---|---|---|
| мьютекс `World.mx` | всё общее состояние мира | шаг такта каждого участника и обработка пакета базой — критические секции; двое роботов не встанут в одну клетку |
| семафоры `g_go[i]` и `g_done` | начало и конец такта | часы делают `sem_post(go[i])` каждому участнику и N раз `sem_wait(done)` |
| семафор `inbox_sem` | ящик базы | производители — узлы связи, потребитель — база (`sem_wait`) |
| счётные семафоры `slots[c]` | разъёмы станции | робот занимает разъём `sem_trywait`, освобождает `sem_post`; если разъёмов нет — «очередь к станции» |
| мьютекс журнала | `ev()` | строки событий из разных потоков не перемешиваются |

Внутри такта участники работают параллельно и захватывают мьютекс мира в произвольном порядке.
Поэтому при одном seed журналы разных прогонов отличаются: seed фиксирует случайные решения
каждого участника (у каждого свой ГСЧ), но не порядок потоков. Взаимоблокировок нет: мьютексы
всегда захватываются в порядке «мир → журнал», а робот не ждёт разъём блокирующим вызовом —
иначе остановились бы часы.

## 3. Интерфейс
- Обычный режим — поток событий по строке на событие: `[такт] ВИД текст`.
- `-m` — каждый такт перерисовывается экран: карта (роботы — цифры, X — авария, выполненные
  цели — заглавные буквы), состояние роботов, сводка, последние события.
- `-v` — дополнительно каждый шаг, такт зарядки и исследования, пересылки узлов.
- Журнал `expedition.log` (`open`/`dprintf`) содержит все события и итоговый отчёт.
- Параметры: встроенный сценарий, файл сценария `-c` (формат — в начале `config.c` и в
  `tests/*.cfg`, новый параметр `charger_slots` — число разъёмов), опции командной строки.

## 4. Запуск и завершение

```bash
make
```

```bash
./expedition -m
```

```bash
./expedition -c tests/t9_queue.cfg -s 5
```

```bash
./expedition -t 0
```

`-t 0` — без ограничения тактов, выход по Ctrl+C. SIGINT и SIGTERM заблокированы в рабочих потоках
(`pthread_sigmask` до их создания) и приходят только в главный поток. Обработчик ставит флаг,
часы заканчивают такт, останавливают участников (`pthread_join`), отправляют базе команду
завершиться и печатают итоги.

| Код | Причина |
|---|---|
| 0 | выполнены все доступные задания |
| 1 | ошибка в параметрах или сценарии |
| 2 | достигнут предел тактов |
| 3 | ресурсы исчерпаны: нет исправных совместимых роботов, кончилась энергия станций или нет прогресса |
| 4 | прервано сигналом SIGINT или SIGTERM, итоги сохранены |
| 5 | нарушен инвариант |

## 5. Результаты
- Демонстрационный сценарий (seed 7): 8 из 9 заданий выполнены за ~105 тактов, 'k' недоступно —
  нет магнитометра. Были потери и дубликаты в узлах связи, повторные передачи, одно назначение
  потеряно и выдано повторно. Инварианты не нарушены.
- 30 прогонов демо с разными seed: 27 — код 0, 3 — код 3 (в опасной зоне разбился единственный
  робот с нужным прибором — законное исчерпание ресурсов).
- `make test`: 10 из 10 проверок. В t9 три робота встают в очередь к станции с одним разъёмом.
- Сборка с ThreadSanitizer: гонок данных не найдено.
